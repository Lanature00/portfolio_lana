01 — Le parcours client

Réserver

Le front est écrit en TypeScript avec React, Vite et Tailwind, découpé en composants. Le client choisit une date, le nombre de personnes, puis laisse ses coordonnées. Depuis son compte, il retrouve ses réservations et peut les annuler.

02 — Le responsive

Sur téléphone

Le même site, pensé pour la main : la mise en page se resserre sur une colonne, sans rien perdre du thème noir et or.

  1. 01

    Le menu se replie

    La navigation laisse place à un bouton à trois traits, en haut à droite, à côté du nom du restaurant.

  2. 02

    Les boutons prennent la largeur

    « Réserver une table » et « Découvrir le menu » s'empilent et occupent toute la largeur : faciles à toucher du pouce.

  3. 03

    La carte sur une colonne

    Les plats passent les uns sous les autres, la photo au-dessus, le nom et la description en dessous.

03 — Le serveur

L'API

Une API REST en Node.js et TypeScript, branchée sur PostgreSQL : sept routes pour tout ce que le site doit lire et écrire. La base tourne dans Docker en local et sur Render en production.

Sécurité

helmet · CORS · limitation du nombre de requêtes · requêtes SQL paramétrées · secrets dans un .env jamais publié

04 — L'authentification

Un jeton

Une authentification JWT à deux rôles : chacun ne voit que ce qui le concerne.

  1. Étape 1

    Connexion

    L'utilisateur s'identifie ; son mot de passe est vérifié avec bcrypt.

  2. Étape 2

    Jeton signé

    L'API renvoie un JWT qui porte son rôle.

  3. Étape 3 · rôle client

    Client

    Crée, consulte et annule ses propres réservations.

  4. Étape 3 · rôle admin

    Admin

    Voit toutes les réservations et change leur statut.

Fin du parcours

En bref

Outils TypeScript · React · Vite · Tailwind · Node.js · PostgreSQL · Docker
Mise en ligne Vercel · Render

Le site est sur Vercel, l'API sur Render ; tout se redéploie à chaque push. L'API est sur une offre gratuite : la première requête peut prendre quelques secondes, le temps qu'elle se réveille.
